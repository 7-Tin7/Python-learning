### 第 6.5 单元：SQL 数据库查询 ⭐ 求职硬门槛（**已完成 34 题**）

| 内容 | 说明 | 技术要点 |

| 聚合与分组（9 题） | 多维汇总统计 | `COUNT` / `SUM` / `AVG` / `MAX` / `MIN` / `ROUND`、`GROUP BY` / `HAVING` |
| 多表连接（10 题） | 关联成本表算毛利润 + 数据质量核查 | `INNER JOIN` / `LEFT JOIN` / `ON`、`UPDATE` + `commit`、`pandas.read_sql()` |

**🔑 本单元的两个亮点**（[`exercises/week6.5/`](exercises/week6.5/)）：

**① 交叉验证** —— 同一批核心指标（总销售额 8148.60 元、水果类别 4502.1 元、
樱桃占比 39.8%）用 **SQL 与 Pandas 各算一遍并逐项比对**，确认两条链路结果一致。

**② 发现并修复一处数据错误** —— 用 `COUNT(DISTINCT)` 做一致性检查时，
发现某商品被错标成两个不同类别。用 `GROUP_CONCAT` 定位到具体订单，
用 `UPDATE + WHERE` 精确修复（仅改 1 行），并量化影响为
25 元销售额、8 元毛利润被归入错误类别。
→ 这次发现让我在原有清洗流程（重复/缺失/空格/异常值/日期格式）之外，
**新增了第 6 项"一致性检查"**。

**SQL ↔ Pandas 对照**（靠已有 Pandas 基础快速迁移）：

| SQL | Pandas |
|-----|--------|
| `SELECT * FROM t LIMIT 5` | `df.head()` |
| `SELECT a, b FROM t` | `df[["a", "b"]]` |
| `WHERE c = 'x'` | `df[df["c"] == "x"]` |
| `WHERE a >= 5 AND b = 'y'` | `df[(df["a"] >= 5) & (df["b"] == "y")]` |
| `ORDER BY c DESC` | `df.sort_values("c", ascending=False)` |
| `SELECT 类别, SUM(销售额) FROM t GROUP BY 类别` | `df.groupby("类别")["销售额"].sum()` |

**⚠️ 踩过的坑（都记在笔记里了）**：表名/列名逐字对齐、**语法位置的标点必须半角**
（全角 `，` `！` 会报错）、`WHERE` 里 `AND` 和 `OR` 混用必须加括号、
`GROUP BY` 的 SELECT 只能放分组列 + 聚合函数、`ROUND` 漏写第二个参数会四舍五入到整数。
