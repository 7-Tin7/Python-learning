## 一、心智模型：数据库到底是什么？

**一句话**：一个数据库文件 = 一个装着多张 Excel 表的文件盒。

```
销售.db  ← 一个文件
   └── 订单   ← 一张"表"（相当于一个 DataFrame）
         ├── 列（字段）：订单编号 / 日期 / 商品名称 / 类别 / 单价 / 数量 / 城市 / 月份 / 销售额
         └── 行（记录）：每一行 = 一笔订单
```

| 数据库说法 | Pandas 说法 | 你熟悉的东西 |
|-----------|------------|-------------|
| 表（table）| DataFrame | Excel 的一个 sheet |
| 列（字段/column）| 列 / Series | 表头那一行 |
| 行（记录/row）| 行 | 一条数据 |
| SQL 语句 | df 的各种操作 | 你对表"提的要求" |

### 关键区别（这个比喻帮你记住 SQL 为什么存在）

- **Pandas**：把**整张表搬到你桌子上**，然后你随便切、随便算。
  → 数据在你自己电脑上，几万行没问题。
- **SQL**：隔着窗口**点菜**，告诉数据库"我只要这几行"，它把结果递给你。
  → 数据可能有**几千万行**存在服务器上，你根本搬不回来，只能"提要求"。

**所以 SQL 的思路是：先想清楚"我要什么"，再写一句话说出来。**

## 二、核心语法：4 个关键词

```sql
SELECT  列名            -- ① 我要哪些列
FROM    表名            -- ② 从哪张表拿
WHERE   条件            -- ③ 只要满足条件的行
ORDER BY 列名 DESC      -- ④ 按什么排序（DESC = 从大到小 / ASC = 从小到大，默认 ASC）
LIMIT   数字;           -- ⑤ 最多给我几行
```

**书写顺序固定是上面这个顺序**，`WHERE` 永远在 `ORDER BY` 前面、`LIMIT` 永远在最后。

> 🔑 **记忆钩子**：`SELECT → FROM → WHERE → ORDER BY → LIMIT`
> 念成："选什么 → 从哪来 → 满足啥 → 怎么排 → 要几行"

### 最常用的 5 个写法

```sql
SELECT * FROM 订单;                              -- 全部列全部行（* = 所有列）
SELECT 商品名称, 销售额 FROM 订单;                -- 只要两列（逗号隔开）
SELECT * FROM 订单 WHERE 城市 = '深圳';           -- 筛选
SELECT * FROM 订单 WHERE 数量 >= 5 AND 类别 = '饮料';  -- 多条件（AND / OR）
SELECT * FROM 订单 ORDER BY 销售额 DESC LIMIT 3;  -- 排序 + 取前 3 名
```

## 三、和 Pandas 对照表（你已经会右边，学左边就快）

| 我想干的事 | SQL | Pandas |
|-----------|-----|--------|
| 看前 5 行 | `SELECT * FROM 订单 LIMIT 5` | `df.head()` |
| 只看某几列 | `SELECT 商品名称, 销售额 FROM 订单` | `df[["商品名称","销售额"]]` |
| 筛选一个条件 | `WHERE 城市 = '深圳'` | `df[df["城市"]=="深圳"]` |
| 筛选多个条件 | `WHERE 数量>=5 AND 类别='饮料'` | `df[(df["数量"]>=5)&(df["类别"]=="饮料")]` |
| 排序（从高到低）| `ORDER BY 销售额 DESC` | `df.sort_values("销售额", ascending=False)` |
| 取前 3 名 | `ORDER BY 销售额 DESC LIMIT 3` | `df.sort_values(...).head(3)` |
| 去重看有哪些取值 | `SELECT DISTINCT 城市 FROM 订单` | `df["城市"].unique()` |

> 💡 **好消息**：SQL 的 `AND` 比 Pandas 的 `&`（还要套括号）顺手得多。
> 你现在是"带着答案学 SQL"——你已经知道分组统计长什么样，第二课学 `GROUP BY` 时会非常快。

## 四、⚠️ 三大坑（Python 学员最容易踩）

### 坑 1：「等于」是**一个** `=`，不是 `==` ！

```sql
❌ WHERE 城市 == '深圳'      -- SyntaxError
✅ WHERE 城市 = '深圳'
```

Python 里 `=` 是赋值、`==` 是判断；**SQL 里没有赋值这回事，`=` 就是判断相等**。
（`!=` 和 `<>` 都表示"不等于"，两个都能用。）

### 坑 2：文字必须用**单引号** `'`

```sql
❌ WHERE 城市 = "深圳"       -- SQL 里双引号是给"列名/表名"用的，写文字会被当成列名 → 报错
✅ WHERE 城市 = '深圳'
```

Python 里单双引号都行，**SQL 里必须单引号**。数字不用引号：`WHERE 数量 >= 5`。

### 坑 3：分号 `;` 和关键字顺序

- 一条 SQL 结尾习惯加分号 `;`（在 Python 里可以不加，但写上更规范）；
- `LIMIT` 必须写在**最后**，`ORDER BY` 必须在 `WHERE` **后面**。

## 五、Python 里怎么跑 SQL？（骨架，背下来就行）

```python
import sqlite3

conn = sqlite3.connect("销售.db")   # ① 打开数据库文件
cursor = conn.cursor()              # ② 拿到执行器

cursor.execute("SELECT * FROM 订单 LIMIT 5")   # ③ 执行 SQL
rows = cursor.fetchall()                       # ④ 取回结果（列表套元组）
for r in rows:
    print(r)

conn.close()                        # ⑤ 关掉
```

| 步骤 | 说法 | 比喻 |
|------|------|------|
| `connect` | 连接数据库 | 打开文件盒 |
| `cursor` | 游标/执行器 | 你的"手" |
| `execute` | 执行 SQL | 把要求递进去 |
| `fetchall` | 取出结果 | 把结果端回来 |

> ⚠️ 建表/插入数据之后必须 `conn.commit()`（提交），否则改动只活在内存里，一关就没了。
> 只是查询（SELECT）不用 commit。

## 八、第 1 课实战避坑记录（真踩过的坑，比笔记更值钱）

**战绩**：6 题 SQL 全部写对 ✅（覆盖 SELECT / WHERE / AND / OR / ORDER BY / LIMIT）
**但**：中间被 4 个坑拦住了 3 次。而这 4 个坑**跟 SQL 语法一个都没关系**——
全部是"名字 / 字符 / 位置"类的老毛病家族。

### 坑 A：表名写错一个字 → 6 题一起死

```sql
❌ select * from 订单表 limit 5     -- no such table: 订单表
✅ select * from 订单   limit 5
```

一个"表"字，让 6 题**全部**报错。
> 🔑 **铁律：表名、列名、变量名 —— 逐字对齐。电脑不会猜你的意思。**
> 家族史：`uft-8` / `--online` / `商品数据_csv` / `tow` / `订单表`

### 坑 B：中文标点混进代码 → 三个列名被当成一个

```sql
❌ select 订单编号，城市，销售额 from 订单
   -- 报错 no such column: 订单编号，城市，销售额
   -- 电脑把【全角逗号】当成了列名的一部分，三个列名读成了一整个名字
✅ select 订单编号, 城市, 销售额 from 订单   -- 半角逗号
```

全角逗号 `，` 是 `U+FF0C`，半角 `,` 是 `U+002C`，**是两个完全不同的字符**，只是长得像。
> 🔑 **铁律：代码里的标点必须是英文的。**
> 黑名单：`，` `。` `；` `：` `（` `）` `“` `”` `‘` `’` 以及**全角空格 `U+3000`**
> 🔑 **动作：敲标点前先按 `Shift` 切回英文输入法，练成肌肉记忆。**
> ⚠️ 半角空格（U+0020）在 SQL 里随便加，没关系；**全角空格照样报错**。

**⚠️ 精确版（重要，别被吓过头）：区分"标点在哪"**

| 标点所在位置 | 全角能用吗 | 例子 |
|-------------|-----------|------|
| **字符串内容里**（给人看的文字）| ✅ **完全没问题** | `print("全部跑完！很好。")` 正常跑 |
| **代码语法位置**（分隔代码元素）| ❌ **一用就崩** | `select a，b`（列名之间）、`x ！= y`（运算符）|

> 🔑 **判断方法：这个标号是给电脑看的（分隔指令），还是给人看的（一句话里）？**
> 给电脑看的 → 必须半角；给人看的 → 中文标点更自然，尽管用。
> **所以：中文注释、字符串里的中文标点，完全不用切输入法。**

### 坑 C：答案写在了"碗外面" → 整个文件跑不起来

```python
❌ show("""
   TODO                           ← 碗里装的还是 TODO，答案没进来
   """, "题 1：查看订单前 5 行")
   select * from 订单 limit 5      ← 掉在碗外，被 Python 当代码读 → SyntaxError

✅ show("""
   select * from 订单 limit 5
   """, "题 1：查看订单前 5 行")
```

`"""..."""` 是一对**容器（碗）**，SQL 必须装进里面递给 `show()`。
掉在外面的 SQL 变成了一句 Python 代码，Python 直接崩溃。
> 🔑 **铁律：内容对、位置错 = 全崩。**
> 家族史：第 6 周"存的格式是空格分隔、读的却按 `|` 拆"—— **同一类问题**：
> 不是写错了，是**放错了地方 / 两套规矩打架**。

### 坑 D：换文件夹 = 悄悄连上一个空数据库

`sqlite3.connect("销售.db")` 是按**脚本自身所在位置**找库的，而且——
**找不到不会报"文件不存在"，而是悄悄新建一个空库**，然后报 `no such table: 订单`。
这个错更难查，因为它把"路径问题"伪装成了"表名问题"。

| 做法 | 结果 |
|------|------|
| 只复制 `.py` 到新文件夹 | ❌ 连上空库 → `no such table: 订单` |
| 复制 `.py` + 复制 `.db` | ⚠️ 能用，但变成**两份数据库**，重跑建库脚本后副本会**过期** |
| 只复制 `.py`，路径改成 `os.path.join(BASE, "..", "销售.db")` | ✅ **一份库，一个真相源**（推荐） |

> 🔑 **铁律：数据集（数据库 / CSV）全项目只留一份，脚本搬家就用 `..\` 指回去。**
> 留副本 = 迟早"改了半处"：改了一份，忘了另一份。

### 今日总口诀（第 1 课 · 避坑版）

```
名字逐字对齐，标点切回英文；
内容装进容器，数据只留一份。

SQL 语法你全对，
栽的全是名字、标点、位置 —— 老毛病换了个马甲而已。
```

## 九、加练复盘（9 题面试风格）+ AND/OR 优先级

**成绩**：4 对 5 错。对的：题 2、3、5、6。错的：题 1、4、7、8、9。

### 9.1 ⭐ AND / OR 的优先级（第 9 题，面试高频考点）

**SQL 里 `AND` 比 `OR` 先算**，跟数学里"先乘除、后加减"一模一样。

```sql
-- 你写的（没有括号）
WHERE 城市='上海' OR 城市='深圳' AND 销售额>200
-- SQL 实际理解成 →  OR 后算，所以变成：
WHERE 城市='上海' OR (城市='深圳' AND 销售额>200)
--        ↑ 上海的订单【全都要】，不管金额！   ↑ 深圳的要筛金额

结果：8 行  ← 混进了 31.5 / 42 / 100 / 200 这些"小额上海订单"，明显不符合要求
```

```sql
-- 加了括号：先算括号里的
WHERE (城市='上海' OR 城市='深圳') AND 销售额>200
--     ↑ 先把两个城市圈成一个整体，再统一筛金额

结果：4 行  ✅ 正确
```

**对比表**（同一份数据，只差一对括号）：

| 写法 | SQL 的理解 | 行数 |
|------|-----------|------|
| `城市='上海' OR 城市='深圳' AND 销售额>200` | `上海全部 OR (深圳且>200)` | **8 行** ❌ |
| `(城市='上海' OR 城市='深圳') AND 销售额>200` | `(上海或深圳) 且 >200` | **4 行** ✅ |

> 🔑 **口诀：`AND` 咬得紧，`OR` 松；要改先后，上括号。**
> **铁律：只要 WHERE 里同时出现 `AND` 和 `OR`，先想"我要不要括号"——不确认就加。**
> （这跟 Python 里 `a and b or c` 的优先级是同一个道理，你写 Python 时也踩得到。）

### 9.2 新坑 E：半份作业 —— 只做后半段，漏了"要哪几列"

题 7、8、9 **同一个毛病**：题目都说了"只要某某列"，你一律写了 `SELECT *`。

| 题 | 题目要的列 | 你写的 | 结果 |
|----|-----------|--------|------|
| 7 | 商品名称、单价 | `*` | 多吐了 7 列没用信息 |
| 8 | 订单编号、销售额 | `*` | 多吐了 7 列 |
| 9 | 订单编号、城市、销售额 | `*` | 多吐了 6 列 |

**这三题的排序/条件你全做对了**（题8 方向也对，默认升序=最低在前），
**只是把"要哪些列"这半句要求漏掉了。**

> 🔑 **铁律：读到题目先圈出"要哪几列 + 什么条件 + 怎么排"三个要求，逐个对着做。**
> 这跟你第 3 周"deposit 加了 return，withdraw 忘了"是**同一个坑**：
> 同一件事有多个要求，你只做了看得见的那一半。
> **写完检查时，回头把题目再读一遍，一项一项打勾。**

### 9.3 老坑重现：拼写 + 全角标点（各一次）

```sql

     家族史：uft-8 / --online / 订单表

题4  ❌ where 类别 ！= '水果'                 -- 全角感叹号 U+FF01
     家族史：昨天刚踩的全角逗号 U+FF0C
```

**注意题 4**：全角标点是**昨天刚讲过**的坑，隔一天又踩了一次。
说明"知道"不等于"做到"——**知道 ≠ 肌肉记忆**。

### 9.4 补充：`ORDER BY` 后面要跟【列名】，不是表名

```sql
题7  ❌ order by 订单 DESC        -- no such column: 订单
     ✅ order by 单价 DESC
```

`ORDER BY 订单` 是"按【订单】这个列排序"，可表里根本没有叫"订单"的列（订单是**表名**）。
> 🔑 表和列是两个不同的东西：**`FROM` 后面放表名，`SELECT`/`WHERE`/`ORDER BY` 后面放列名。**
