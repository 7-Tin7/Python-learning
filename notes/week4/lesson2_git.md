# 第 4 周 · 第 2 课：Git 版本控制 —— 给代码装"时光机"

## 一、为什么需要 Git？（先看痛点）

你写项目时是不是经历过这些：
- 改代码改崩了，想回到"昨天还能跑"的版本 → **没法回退**
- 项目文件夹里出现 `main.py`、`main_改.py`、`main_最终版.py`、`main_真的最终版.py` → **一片混乱**
- 混血代码越补越乱，想推倒重来 → **不敢删，怕丢东西**

**Git 就是解决这些的**：给项目装"存档系统"，每个存档点叫**提交（commit）**，
可以随时查看历史、回到任何版本。

**一句话理解**：Git = 游戏的**存档读档**功能，你写代码就是"打关卡"。

## 二、核心概念（3 个区域）

```
工作区（你正在编辑的文件）
    ↓ git add        （把改动"打包"放进暂存区）
暂存区（准备提交的改动）
    ↓ git commit     （存成一个"存档点"）
版本库（所有历史存档，永久保存）
```

**比喻**：写作业 → `git add` 是把作业放进书包 → `git commit` 是交作业存档。

## 三、5 个必会命令

### 1. git init —— 开启版本控制（只做一次）
```bash
git init
```
在项目文件夹里运行，会生成 `.git` 隐藏文件夹（存档库）。

### 2. git status —— 看现在什么状态（最常用！）
```bash
git status
```
告诉你：哪些文件改了、哪些还没提交。**不知道下一步干嘛时，就敲它！**

### 3. git add —— 把改动加入暂存区
```bash
git add 文件名          # 加某个文件
git add .               # 加所有改动（常用）
```

### 4. git commit —— 存档！
```bash
git commit -m "完成猜数字游戏"
```
`-m` 后面是**说明**（写清楚这次改了什么，以后好找）。

### 5. git log —— 查看历史存档
```bash
git log                 # 详细历史（按 q 退出）
git log --oneline       # 简洁版（推荐）
```

## 四、日常操作流程（背下来）

```bash
# 改了几个文件后：
git status                    # ① 看看改了啥
git add .                     # ② 全部加入暂存区
git commit -m "描述这次改动"   # ③ 存档
```

**习惯**：**每完成一个小功能就存档一次**，别攒到一天结束才提交。
好的存档说明示例：
- "添加任务删除功能"
- "修复输入 abc 崩溃的 bug"
- "完成学生成绩统计功能"

## 五、时光机功能：回退到历史版本

```bash
git log --oneline              # ① 找到要回去的存档号（如 a1b2c3d）
git reset --hard a1b2c3d       # ② 硬回退到那个版本！（小心：会丢弃之后的改动）

# 或者只想撤销对某个文件的改动（还没提交时）：
git restore 文件名
```

⚠️ `reset --hard` 是"强制回到过去"，**之后未提交的改动会丢失**——用之前想清楚。

## 六、GitHub：给代码找个"云备份 + 作品展示厅"

**GitHub = 网上的代码托管网站**，作用：
1. **云备份**：电脑坏了代码还在
2. **作品集**：求职时给 HR/面试官看的"活简历" ⭐
3. **协作**：多人一起开发同一个项目

### 流程：
```bash
# ① 注册 GitHub 账号（网页操作）
# https://github.com

# ② 网页上新建仓库（New repository），拿到仓库地址

# ③ 本地关联远程仓库
git remote add origin https://github.com/你的用户名/仓库名.git

# ④ 把本地存档推上去（第一次用 -u）
git push -u origin main

# 之后的推送：
git push
```

## 七、PyCharm 图形界面（更简单！）

PyCharm 内置 Git，不用敲命令也能做：
- **右上角绿色 √ 勾** = 提交（相当于 add + commit）
- **右下角 Git 分支** = 查看历史、切换版本
- **顶部菜单 Git → Push** = 推送到 GitHub
- **菜单 Git → GitHub → Share Project on GitHub** = 一键把项目传到 GitHub

（建议：**先学命令理解原理**，再用 PyCharm 提高效率。）

## 八、记忆口诀

> init 开仓库，status 看状态；
> add 装书包，commit 存档点；
> log 查历史，reset 回过去；
> push 上云端，GitHub 当作品集；
> 小步常提交，说明写清楚。

## 九、常见坑

| 坑 | 说明 |
|----|------|
| 忘了 git add 就 commit | 提示 "nothing to commit"，改动没进暂存区 |
| commit 说明写"改了一下" | 以后自己都看不懂，要写清楚改了什么 |
| 一天才提交一次 | 出问题回退会丢一天的工作，要小步提交 |
| 在错误目录 git init | `.git` 会建在当前目录，注意路径 |
| push 报认证错误 | 首次推送需要登录 GitHub（PyCharm 会弹窗引导）|
