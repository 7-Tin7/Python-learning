## 一、这次项目你干了什么

**起点**：一个"有几个功能用不了"的半成品
**终点**：一个健壮的学生成绩管理系统（字典存数据、isdigit 验证、统计算法正确）

**过程**：前后修了 6 轮 bug。每一轮修的不是"抄答案"，而是理解一个概念。

---

## 二、6 轮 Bug → 6 条铁律（这次项目的最大收获）

| 轮次 | Bug 现象 | 根因 | 铁律 |
|------|---------|------|------|
| 1 | 查找/修改显示错人 | 用了上次添加残留的 `name` 变量 | **新输入的值用新变量** |
| 2 | 删除直接崩溃 | 字典调用了列表的 `.remove()` | **删字典用 `del 字典[键]`** |
| 3 | 查看显示颠倒 | `items()` 拆包顺序写反 | **`for 键, 值 in items()`，名字要对上内容** |
| 4 | 统计结果全错 | 成绩存成了字符串 | **input 先 `int()` 再存** |
| 5 | 统计逻辑乱 | 遍历键、循环里打印、空检查错位 | **擂台套路：循环里只更新，循环外才打印** |
| 6 | 输入 abc 崩溃 | `int()` 在验证前执行 | **先检查（isdigit）后转换（int）** |

**发现规律了吗**？6 条铁律里，至少 4 条是"**列表习惯误用到字典**"或"**检查顺序错**"——它们不是孤立的错误，而是同一类思维误区的不同表现。

## 三、复盘：这次项目证明你学会了什么

### ✅ 已经内化的能力

1. **字典是你的主场**：`in` 判断、`d[键]=值` 添加/修改、`del` 删除、`items()/values()` 遍历——全通了
2. **验证意识**：从"输入什么都收"进化到"先检查后转换"，这是真实软件的基本功
3. **算法套路**：累加套路（平均分）+ 擂台套路（最大最小）——数据统计的两板斧
4. **调试能力**：从"报错就慌"到能定位"是崩溃还是结果错"

### ⚠️ 还需警惕的倾向

1. **复制粘贴自己的代码时不思考**：功能 2 的 `for score, name` 就是"抄自己前面写对的代码时抄反了"
2. **验证写成"马后炮"**：想检查但放在了转换之后——**检查必须发生在可能出错的操作之前**
3. **一个项目混太多概念时容易乱**：这正是第 2 周中段你"头脑混乱"的原因——**用学习地图和万能骨架来归位**

## 四、回顾"万能骨架"——你的所有项目其实是一个程序

```
初始化容器 → while True → 显示状态 → 菜单 → if/elif/else → break
```

| 项目 | 容器 | 学到的 |
|------|------|--------|
| 猜数字 | 变量 | while / if / random |
| 购物清单 | 列表 | append / remove / enumerate |
| 数字统计器 | 列表 | 累加 / 擂台套路 |
| 好友统计 | 元组+集合 | 拆包 / 去重 |
| 通讯录 | 字典 | d[键]=值 / items() |
| 仓库管理 | 字典+列表 | 字典查价 / join |
| **成绩管理** | **字典** | **以上全部 + 验证 + del** |

**第 2 周 = 一个骨架 × 七种容器**。你能走到这，说明"换容器"的能力已经建立。

---

## 五、给未来写代码的 3 条建议（带走它）

1. **写之前先画骨架**：先写 `while True` + 菜单 + 空壳分支，再往每个分支填逻辑——不要一上来就写细节
2. **每写完一个功能立刻测试**：别攒到最后一起测（这次项目的 bug 大多是"攒"出来的）
3. **报错信息是你的朋友**：`ValueError`、`AttributeError`、`KeyError`——看到报错类型，你就知道是哪类问题（转换错/方法错/键不存在），这次项目你其实已经见过它们全家了

## 六、下一步预告

第 2 周学的所有"容器"（列表/字典/函数）都是**数据层面**的组织工具。
第 3 周开始学**类（class）**——把"数据 + 操作数据的函数"打包成一体。

**预告**：你的三角洲仓库、学生成绩系统，以后都能用类重构成"每个东西自带方法"的高级形态。
比如"学生"会自带"算平均分"的能力，而不是你写一堆散落的函数。

> 复盘的真正意义：**不是你记住了答案，而是下次遇到类似问题，你能一眼认出它**。
