### ⭐⭐ 给你的第一个大礼：Tab 键

你的**头号错误模式是"拼写/字母顺序错误"**（`uft-8`、`--online`、`tow`、`form`…）。
这在 Python 里只能靠你自己检查，**但在 Linux 里有解药**：

| 按键 | 作用 |
|------|------|
| **Tab** | **自动补全**：敲 `cd 服务日` 然后按 Tab，自动补成 `cd 服务日志_0918.txt` |
| **Tab Tab** | 按两下，**列出所有可能的补全**（记不住文件名时最有用）|
| **↑ / ↓** | 翻历史命令（不用重新敲长命令）|
| **Ctrl + C** | 强制中断当前命令（卡住了就按它）|
| **Ctrl + L** | 清屏（比敲 clear 快）|

⚠️ **核心心法**：
**凡是文件名、目录名、命令名，一律用 Tab 补全，不要手敲。**
这样你就**在物理上不可能**把文件名拼错。

→ 在第 6.5 单元，你因为拼写错误栽过好几次（`form`/`from`、`--online`）。
**Tab 键就是治这个的。这一课你至少要按 50 次 Tab。**

### ⚠️ 你的第 2 个老坑在这里也会犯：全角标点

中文输入法混进**语法位置**的标点（`，` `；` `（` `）`）在 Linux 里同样是灾难：

```bash
cd 日志，ls        # ← 这里的「，」是全角，命令直接报错
cd 日志; ls        # ← 正确：必须是半角分号
```

**Linux 里比 Python 更容易中招**，因为命令行输入框里没有语法高亮提醒你。

🔑 **动作（不是知识）**：**敲任何标点前先看输入法状态**，
在终端里尽量**切到英文输入法**。这是你第 6.5 单元就被提醒过的老问题，
这次我们换个战场再练一遍。

🔍⭐ **思考题（本课最重要的一题，自己跑，别猜）**

下面三条命令的结果**一样吗**？各是多少？

```bash
grep -c    ERROR 日志/*.txt
grep -c -i error 日志/*.txt
grep -o -i error 日志/*.txt | wc -l
```

提示两个方向：
1. `grep -c` 数的到底是"**行**"还是"**次数**"？
2. 有没有哪一行是"大小写不同、但也算匹配"的？

<details>
<summary>跑完再点开对答案（⚠️ 先自己跑！）</summary>

**正确答案：8 / 9 / 11**（我已经实跑核对过）

| 命令 | 结果 | 数的是什么 |
|------|------|-----------|
| `grep -c ERROR 日志/*.txt` | **8** | 含大写 `ERROR` 的**行数** |
| `grep -c -i error 日志/*.txt` | **9** | 含任意大小写 `error` 的**行数** |
| `grep -o -i error 日志/*.txt \| wc -l` | **11** | 忽略大小写的**出现次数** |

**三处关键差异的解释**：

**① 为什么 8 → 9？**
因为日志里有这么一行：
```
2026-09-19 11:00:09 WARN  上一次同类 error 已记录到 error.log
```
这行是 `WARN` 级别（不是 ERROR），但里面有小写 `error`。
加 `-i` 之后它被算进来了 → 多 1 行。

**② 为什么 9 → 11？（最容易错的一步）**
因为 **`grep -c` 数的是"行"，`grep -o` 数的是"次数"**：

- 上面那行 **1 行里出现了 2 次** `error`（`error` + `error.log`）
- 还有这一行：`... ERROR 请求体解析失败 json.decoder.JSONDecodeError`
  里面藏着 `JSONDecodeError` → 含一个小写 `error`，但**这行本来就在 8 里算过**了

所以：**11 次出现，分布在 9 行里。**

**③ 用 `grep -o` 数次数的写法**
`grep -o` = only-matching，把每个匹配**单独打印成一行**，
再用 `wc -l` 数行 → 就等于数次数。**这是"数次数"的标准套路。**

---

📌 **这一题为什么重要**：
你在第 6.5 单元有过**"只看前几行就交作业"**的问题（那个 6/11 行错的统计结果）。
这一题就是同一个毛病的照妖镜：
**"ERROR 有几条"这个需求，本身就有歧义**——
是"有几行报错"还是"报错出现几次"？
**问清楚需求再写查询**，这是从"会写代码"到"能干活"的分界线。

### 第七组：管道与重定向（⭐ 命令行的灵魂）

| # | 任务 | 命令 | 含义 |
|---|------|------|------|
| 7-1 | 把明细存成文件 | `grep ERROR 日志/*.txt > 报告/错误明细.txt` | `>` **覆盖**写入 |
| 7-2 | 追加而不是覆盖 | `>> 文件` | `>>` **追加** |
| 7-3 | 把上一条的输出喂给下一条 | `grep ERROR 日志/*.txt \| wc -l` | `\|` **管道** |

💡 **比喻**：
- `>` 重定向 = **接根管子，把结果导到文件里**（像水流改道）
- `|` 管道 = **流水线**：上一个命令的产物交给下一个命令当原料

对照你熟的 Python：`>` 就像 `print(..., file=f)`，
`|` 就像 `f(g(x))`——**把函数串起来**。

⚠️ **`>` 和 `>>` 的区别极其重要**：
- `>` **清空**原文件再写（不小心就把你之前的结果冲掉了）
- `>>` 在末尾**追加**

### 第八组：权限 ⭐ 面试会问

| # | 任务 | 命令 | 说明 |
|---|------|------|------|
| 8-1 | 看权限 | `ls -l 检查作业.sh` | 看开头的 `-rw-r--r--` |
| 8-2 | 加可执行权限 | `chmod +x 检查作业.sh` | 再做 8-1，会变成 `-rwxr-xr-x` |

**怎么读 `-rwxr-xr-x`**（一共 10 位）：

```
-  rwx  r-x  r-x
│   │    │    │
│   │    │    └── 其他人(other)：可读、可执行，不可写
│   │    └─────── 同组人(group)：可读、可执行，不可写
│   └──────────── 你自己(user)：可读、可写、可执行
└──────────────── 文件类型：- 是文件，d 是目录
```

- `r` = read（读）· `w` = write（写）· `x` = execute（执行）
- `chmod +x` = 加上可执行 · `chmod -x` = 去掉
- 数字写法：`r=4 w=2 x=1` → `755` = `rwxr-xr-x`，`644` = `rw-r--r--`

🔍 **思考题**：`.sh` 脚本用 `bash 统计.sh` 能跑，
那为什么还要 `x` 权限？
（提示：试试 `./统计.sh`，看没有 `x` 时报什么错）

## 五、避坑预告（先看一眼，遇到时会有印象）

| # | 坑 | 症状 | 解药 |
|---|-----|------|------|
| 1 | **全角标点** | `cd 日志，ls` → `command not found`，报错信息很怪 | 敲标点前看输入法，终端里切英文 |
| 2 | **`rm` 没回收站** | 删了就没了 | 先 `ls` 确认，再 `rm` |
| 3 | **`cp` 忘 `-r`** | `omitting directory` | 拷目录必须 `cp -r` |
| 4 | **`less` / `top` 卡住** | 屏幕不动了，"电脑死了" | **按 `q` 退出**（不是 Ctrl+Z）|
| 5 | **`>` 冲掉文件** | 之前的结果没了 | 追加用 `>>` |
| 6 | **`*` 通配符太宽** | 把不该拷的也拷进去了 | 用具体文件名 |
| 7 | **文件名大小写** | Linux **区分大小写**，Windows 不区分 | `服务日志.txt` ≠ `服务日志.TXT` |
| 8 | **路径写错** | `No such file or directory` | **用 Tab 补全**，别手敲 |
| 9 | **没 `x` 权限** | `./统计.sh` → `Permission denied` | `chmod +x` |
| 10 | **Windows 换行符** | 脚本报 `$'\r': command not found` | ⚠️ 见下面的特别提醒 |

### ⚠️ 特别提醒：第 10 条是个真问题

我体检时发现你的 Git 配置是 **`core.autocrlf = true`**——
这意味着 **`.sh` 文件被 Git 检出时会带上 Windows 的换行符（CRLF）**，
拿到 Linux 里跑就会报：

```
bash: ./统计.sh: /bin/bash^M: bad interpreter: No such file or directory
                 ↑ 这个 ^M 就是多余的 \r
```

**这个坑很隐蔽**：文件看着完全正常，就是跑不了。

✅ **我已经处理了**：在仓库根目录加了 `.gitattributes`，规定 `*.sh` 一律用 LF。
这样以后不管在哪个系统检出，`.sh` 都是对的。

📌 **你只要知道有这回事**——**"跨系统的换行符"是真实存在的工程问题**，
面试聊到部署/协作时提一句会显得你真干过活。
